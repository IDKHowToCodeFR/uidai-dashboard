System Overview & Architecture

The system separates heavy analytical calculations and multi-tenant persistence (FastAPI Backend) from high-density interactive charting (Dash & Plotly Frontend). Ingestion streams run non-blocking background threads that feed live percentage bars directly into client WebSockets, with dedicated pure parsing engines and idempotent database repositories.

Domain Model & Operational Metrics

Adheres to strict Domain-Driven Design (DDD). Metrics strictly follow telecom and BPO operational standards:

Domain Metric Canonical Definition Mathematical / Logic Model
Service Level (SL %) Percentage of answered calls connected within threshold (≤20s). SL % = (ACD_20s / (Offered - ABAN_10s)) * 100
Weighted Average SL Aggregated volume-weighted percentage across historical intervals. Sum(ACD_20s) / Sum(Net_Offered) * 100
Average Handle Time (AHT) Total time agent spends processing caller (Talk + Hold + Wrap). AHT = (Talk + Hold + ACW) / Total_ACD_Calls
Average Hold Time Average caller hold duration per answered interaction. Avg_Hold = Total_Hold_Time / Total_ACD_Calls
DNIS Company Resolution Identification of vendor attribution in UniMate IVR streams based on dialed number prefix. DNIS starts with 56 → Digitech | 57 → NSB
Dynamic Time Bucketing Auto-resampling aggregation according to query interval span. ≤7d: Daily | >31d: Weekly | >90d: Monthly
Lazy Password Upgrading Transparent cryptographic hash migration upon valid login. if pwd_context.needs_update(): rehash()
Provenance Audit Trail Strict attribution of operations with forwarded IP, User Agent, and endpoint. Captured in AuditLog from X-Forwarded-For

07

Architectural Decision Records (ADRs)

ADR 0001 Asynchronous WebSocket Progress Streaming

Context: Uploading 50MB workbooks took 5-15s, which risked timing out synchronous HTTP requests.
Decision: Adopted a dual-channel upload pattern: WebSocket receives progress percentage broadcasts while FastAPI worker runs in BackgroundTasks.
Result: Zero browser freezing, immediate visual feedback.

ADR 0002 Relational Storage with Idempotent Upserts

Context: Files are often re-uploaded with overlapping timestamps.
Decision: Enforce composite unique constraints (company, language, call_timestamp) and (ucid), applying SQLite ON CONFLICT DO UPDATE.
Result: Guaranteed data consistency with zero duplicate records.

ADR 0003 Client Header Forwarding for Compliance Audit

Context: Frontend acts as an internal proxy, which would mask client IPs as 127.0.0.1.
Decision: Forward original X-Forwarded-For and User-Agent headers from Dash to FastAPI.
Result: Non-repudiation audit logging for regulatory standards.

ADR 0004 Pure Domain Parsers & Repository Pattern Separation

Context: Combining file parsing, KPI calculation, and database persistence created tight coupling and testing hurdles.
Decision: Extracted pure domain parsers (CCFParser, UniMateParser) and dedicated persistence repositories (CCFDatabaseRepo, UniMateDatabaseRepo).
Result: Deep modules, clean seams, and trivial extensibility for future datasets.

ADR 0005 Dynamic DB-Configured Directory Sweep

Context: Scheduled ingestion required hardcoded folder paths, preventing runtime management of ingested telemetry types.
Decision: Integrated APScheduler with ActiveFoldersConfig reading enabled folders from database Setting records every 3 minutes.
Result: Zero-downtime dynamic folder management and hands-free automatic file ingestion.
